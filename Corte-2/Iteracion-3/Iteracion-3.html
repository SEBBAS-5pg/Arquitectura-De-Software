Iteración 3: El Nivel de Componentes y la Agilidad

Para mi tercera intervención, quiero poner sobre la mesa el nivel más polémico del Modelo C4: El Nivel 3 (Componentes). Según Simon Brown, este es el nivel donde más errores de diseño se cometen.

1. La Trampa de la "Arquitectura de Erosión"

El mayor peligro en este nivel es la erosión arquitectónica: cuando el diagrama dice una cosa y el código hace otra. En equipos grandes, los componentes a menudo terminan acoplados de formas no previstas.

¿Cuándo usar el Nivel 3? ¿Cuándo omitirlo?
Sistemas complejos con lógica distribuida. Sistemas simples o CRUDs básicos.
Equipos grandes que requieren Onboarding. Equipos de < 5 devs.

"Solo crea el diagrama si el esfuerzo de mantenimiento vale la comunicación de diseño... hay que equilibrar el modelo con la agilidad."
— Brown, S. (2015).

2. Reflexión sobre Componente vs. Clase

Es vital no confundir un componente con una clase. Un Componente es una agrupación de código que entrega una funcionalidad completa.
